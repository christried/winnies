## PR body

## Summary

Ticket #269, after #270. The helper's sign-in and its `api/winnies` read go through `context.request`, which runs in Node and does not read `HTTPS_PROXY`. In a cloud container the proxy is what adds the real bypass header, so those two calls met Vercel's login while the browser itself got through.

```diff
 shots.mjs
-  context = browser.newContext({ reducedMotion })
+  context = browser.newContext({ reducedMotion, proxy: HTTPS_PROXY set ? { server: HTTPS_PROXY } : none })
```

## Evidence

From a cloud session on the `winnies` environment, the bypass secret saved there as a network secret (header `x-vercel-protection-bypass`, no prefix):

- **Before:** `BASE_URL=https://staging.winnies.christried.me node scripts/shots.mjs --out <dir> --as cloud269` → `Vercel login answered instead of the app`, exit 1. `curl` to staging: 200; the container's Chromium alone: 200, title "Winnies Staging"; `context.request` without a proxy: 302 to vercel.com; with it: 200.
- **After:** the same command with `--seed` → both screenshots saved, title "1:45:02 · Winnies Staging", `no console errors`, exit 0. The 1440 px shot shows the dev Owner's Workspace with the dummy set.
- `pnpm lint`, `pnpm typecheck` and `pnpm test` green on the head.
